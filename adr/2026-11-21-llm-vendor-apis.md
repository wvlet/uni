# wvlet.uni.ai: wire-exact LLM vendor models and a neutral model for conversion

## Context

Scala apps call the Anthropic Messages, OpenAI Responses and Chat Completions, and Gemini `generateContent` APIs (on the vendors' own hosts, Vertex AI, and Amazon Bedrock), and proxies serve one vendor's API with another vendor's models (Claude Code on OpenAI models, OpenAI clients on Claude). Each API has its own JSON shape and adds block and event types every few months. The old `uni-agent` chat abstraction was removed in 2026-06; it was a client abstraction, not a wire model.

## Decision

- **Part of the `uni` artifact**, not a separate module. It is about 8k lines with no dependencies, like the storage clients and the MCP server that `uni` already holds. Scala.js and Native link only what an app calls, and all modules release together anyway, so a separate artifact would only add a dependency line for users and agents. Move it out if it ever needs a dependency (a tokenizer, for example).
- **One package per wire protocol**, not per host: `wvlet.uni.ai.anthropic` (Anthropic API, Vertex `rawPredict`, Bedrock's Anthropic API), `.openai` (Responses, Chat Completions, compatible servers, Bedrock's OpenAI API), `.gemini` (AI Studio and Vertex). Shared code and the neutral model sit in `wvlet.uni.ai`.
- **Hand-written `JsonCodec`s on `JSONValue`, not derived Weavers.** Derived codecs write Scala field names and class-name discriminators. They cannot express snake_case keys, key-tagged unions (`{"functionCall": ...}`), omitted absent fields, or unknown-type passthrough. `JsonCodec.weaver` adapts a codec for routers and RPC.
- **Forward compatibility**: every union has `Unknown(raw)`, and top-level requests and responses keep unmodeled fields in `extra`, so a proxy forwards what it does not model.
- **A neutral model in the shape of the Vercel AI SDK provider spec**: typed parts with `providerMetadata` keyed by vendor, stream parts that open, grow, and close blocks by id, `FinishReason(kind, raw)`, and `LlmUsage` in one convention (input includes cache tokens; output includes reasoning). LiteLLM, claude-code-router, and Bifrost instead use Chat Completions as the hub and bolt on side channels for signatures and block order. N vendors need 2N converters, not N².
- **Stateful stream converters, one per stream**: `StreamDecoder` (vendor → neutral) and `StreamEncoder` (neutral → vendor), each with `finish()`. The Chat Completions decoder emits `Finish` only at the end, because usage arrives after the finish chunk.
- **Cross-vendor reasoning carriers**: OpenAI encrypted reasoning and Gemini thought signatures ride in Anthropic thinking `signature`s, and Anthropic signatures ride in OpenAI `encrypted_content`, with a `wvlet.uni.ai:<vendor>:` prefix. Clients return these blocks verbatim, so the next turn recovers the data. Gemini function calls in history without a signature get Gemini's documented `skip_thought_signature_validator`. Carriers go only toward clients (`fromLlmResponse`, `StreamEncoder`). A request to a vendor API (`fromLlmRequest`) drops another vendor's reasoning, because the API would reject a signature it did not issue.
- **Clients never retry**; a retried completion is billed twice. Errors become `LlmApiException`, which unwraps `HttpMaxRetryException`. Bedrock auth is a Bedrock API key (`x-api-key` on the Anthropic API, `Authorization: Bearer` on the OpenAI API) or SigV4 (service `bedrock`) through `wvlet.uni.storage.SigV4`. Vertex auth uses `GoogleCredentialsProvider` with the cloud-platform scope.
- **Bedrock through the vendors' own APIs, not Converse.** bedrock-runtime serves the Anthropic Messages API at `/anthropic/v1/messages` (SSE streams, `model` in the body) and the OpenAI Responses and Chat Completions APIs at `/openai/v1`. `AnthropicHost.Bedrock` and `OpenAIConfig.bedrock` reuse those codecs, streams, and converters. The first version also modeled Converse (with an AWS event-stream decoder) and InvokeModel; both were removed, a fourth wire model of about 1.5k lines that only reached the same models. The bedrock-mantle endpoint is not supported, because AWS is deprecating it.

## Consequences

- Lost with Converse: Converse-only request features (the Guardrails config, `additionalModelRequestFields`, `cachePoint`), Bedrock models that offer neither an Anthropic nor an OpenAI API (some Llama, Mistral, and Titan models), and serving the Converse format to clients. `countTokens` is Anthropic-API only, because Bedrock documents `count_tokens` only on mantle. If those are needed again, add Converse back as its own package.

- New vendor fields need a codec change to become typed, but they pass through as `extra` or `Unknown` until then.
- Carrier signatures are opaque to clients, but a client that inspects or drops thinking blocks loses cross-vendor reasoning; the next turn then runs without it.
- The Chat Completions and Gemini stream encoders drop `LlmStreamPart.Error`, because neither format has an error event; the stream then ends with a normal finish reason.
- Not modeled yet: Gemini `partialArgs` streaming (`streamFunctionCallArguments`), OpenAI built-in tool events (kept as `Unknown`), and Anthropic Files/Batches endpoints.
