# CSV and TSV in `wvlet.uni.text.csv`

## Context

Uni had no CSV codec. Rows should decode into case classes with Weaver, large files should stream, and the same code must run on JVM, Scala.js, and Native. "TSV" covers two incompatible conventions: CSV with a tab delimiter and `"` quoting (spreadsheets), and unquoted fields with backslash escapes and `\N` for null (PostgreSQL `COPY`, MySQL).

## Decisions

- **One package, presets as values.** `CSV` and `TSV` are instances of `CSVFormat`, and the `withXXX` methods derive other dialects. `CSVEscapeStyle` (`Quoted`, `Backslash`, `Plain`) is the only difference between the TSV conventions.
- **Plain `TSV` uses backslash escapes**, the database convention, because it never needs quotes and has a real null marker. `TSV.quoted` reads spreadsheet TSV. The user chose this default.
- **A pull parser over text chunks, not `ScannerBase` or `LineReader`.** Those work on a whole `IArray[Char]`. Pulling one character at a time from an `Iterator[String]` lets a field, a `""`, or a `\r\n` span chunks without an explicit resumable state.
- **Missing values are dropped before Weaver decodes the row.** A field equal to the null string (an unquoted empty field for CSV, `\N` for TSV) becomes a missing key, not a JSON `null`. `CaseClassWeaver` rejects a null for a non-`Option` field, while a missing key takes the field's default or `None`. A quoted `""` stays an empty string.
- **Blank lines are skipped, except in a one-column file.** A one-column file can store an empty value only as an empty line, so once the first record has one field, an empty line is a row. Before the first record, blank lines are always skipped.
- **The writer refuses ambiguity instead of guessing.** In the `Backslash` and `Plain` styles, a value whose written text equals the null string throws `IllegalArgumentException`, because it would read back as missing. The `Quoted` style quotes such a value.
- **Positional mapping uses `CaseClassWeaver.fieldNames`** (`private[uni]`) when there is no header and no `withColumns`. No `Surface` or inline macro is needed in the CSV API.
- **Bytes come in through `CSVReader.decodeUTF8`.** `Iterator[String]` and `Iterator[Array[Byte]]` erase to the same type, so they can't be two `reader` overloads. The decoder carries an incomplete UTF-8 sequence (at most 3 bytes) to the next chunk and decodes with `String(bytes, UTF_8)`, so all three platforms run the same code without relying on an incremental `CharsetDecoder`.
- **Values are not type-guessed.** Weaver converts each text value to the target field type, and guessing would break IDs like `007`.

## Consequences

- On Node.js, `readFile` reads the whole file first (a limit of `FileSystem.readChunks`), and browsers can't read files; callers stream through `reader(chunks)`.
- A trailing empty line in a one-column file reads as one more missing value.
- Lossless round-trip editing, delimiter detection, and Parquet/Arrow bridges are left for later.
