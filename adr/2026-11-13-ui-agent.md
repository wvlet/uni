# UiAgent: AI agents read and operate uni-ui through a component registry and typed actions

## Context

Agents that drive a UI today read screenshots or the accessibility tree and guess which element to click. A uni-ui app already knows more than that: each component has a kind, an accessible label, a typed value, its items, and the changes it can make, and every change goes through `ChangeGate` (`2026-11-13-uni-ui-change-details.md`). The plan in `plans/2026-11-13-ui-sdk-learnings.md` (step 4, design note `plans/2026-11-13-ui-agent.md`) proposes a bridge that exposes this to agents while the app keeps control over what they see and do. It is a new public surface, and it is the tool surface agents call, so the choices are recorded here.

## Decision

- **Registry, not DOM scraping.** Components attach an `AgentBinding` to their root element with `AgentRegistry.attach(binding)`, a `RefBinding` to a `DomRef` subclass. The binding is set when the renderer applies the modifier and removed on unmount, without waiting for the asynchronous `onMount`. A snapshot walks the DOM under the root and reports the registered elements in page nesting, so overlays (portaled to `<body>`) appear as top-level nodes.
- **Opt in.** Nothing is exposed until the app calls `UiAgent.install(policy)`. Bindings register regardless, which costs one property per component element.
- **Fixed actions per kind.** button `press`, textfield `setText`, select/tabs/list/tree `select`, table `sort`, menu `open`/`close`, menuitem `press`, dialog `close`. An action's value schema comes from the component's own data: a `Select[Region]` lists its option labels as a JSON Schema `enum`, so agents pick an item rather than construct an `A`. Repeated labels get ` (2)`, ` (3)` suffixes.
- **Agent changes go through `ChangeGate`.** `act` runs the action inside `ChangeSource.withSource(ChangeSource.Agent)`, so `onChange` sees `source == Agent` and can cancel. `act` reports `canceled` when it did. `press` clicks the element, so the app's own click listeners run as they do for a person.
- **Refs.** An explicit `UiAgent.ref("name")` (`data-agent-ref`), else `kind:label-slug`, made unique with `-2`, `-3`, and kept while the component stays mounted.
- **Permissions.**
  - `AgentPolicy`: `allowAll` (the default), `readOnly`, or `allow(target => ...)`. Snapshots list only allowed actions.
  - `UiAgent.hidden` (`data-agent-hidden`) removes a subtree, and so do `hidden`, `inert`, and `aria-hidden="true"`. A modal dialog therefore hides what is behind it.
  - `UiAgent.secret` (`data-agent-secret`) and `type="password"` read as `<redacted>`, in snapshots and in the change feed.
  - `UiAgent.confirm(message)` (`data-agent-confirm`) on a component or an ancestor makes `act` wait for the human. The default asks with an `AlertDialog`.
  - Disabled components list no actions, and `act` refuses them.
- **Nothing acts while a confirmation waits.** Every `act` is refused until the human answers. An error, an answer that never comes (completion without a value), or `uninstall()` releases the lock as `declined`. Otherwise the agent could press the dialog's own Allow button; a test caught exactly that.
- **Change feed.** `ChangeGate.write` reports every handled change to `AgentRegistry.report`. Committed ones go to `subscribe` listeners, named by the component that owns the target `RxVar` (bindings list their `states`). Each installed `UiAgent` keeps the latest 500 non-agent changes behind a cursor, for `changes(since)`.
- **Wire API.** `wvlet.uni.agent.UiAgentApi` lives in `uni`, so an Electron main process or a JVM client can use it without uni-ui. It has `snapshot`, `query`, `act`, and `changes`, and returns JSON text, which lets each action carry a real JSON Schema without a `Weaver` for `JSONValue` and passes through every transport unchanged. `MCPServer.withTools[UiAgentApi](agent.api)` serves it as MCP tools.
- **WebMCP.** `agent.installWebMcp()` registers the same tools with `document.modelContext.registerTool(tool, { signal })` when the page has it, and does nothing otherwise. Tool calls run through `MCPServer.handleMessage`, so argument decoding and errors match the MCP server. Canceling the result aborts the signal. This is the current Chrome API (flag or origin trial); the earlier `navigator.modelContext` and `provideContext()` were removed from the proposal.
- **Tests use the same API.** `DomTestSupport` lives in uni-test, below uni-ui, so it can't know component kinds. Tests call `UiAgent` in process instead.

## Alternatives

- **Snapshot the accessibility tree.** It loses typed values and per-action schemas, and it is what screenshot and a11y-tree agents already do poorly.
- **Register in `onMount`.** `onMount` fires from a `MutationObserver` a tick after rendering, so a snapshot taken right after an action would miss new components such as an opened menu's items.
- **Infer actions from method names (`set*`, `open`, `toggle`).** Untyped, and it breaks on renames.
- **Typed case classes on the wire.** They need a `Weaver` for embedded JSON Schemas and buy little, since every consumer is an agent reading JSON.

## Consequences

- Components without a binding are invisible to agents. Dock, Panes, Toast, CommandPalette, and Tree expand/collapse are follow-ups.
- List items come from the list's typeahead label when one is set, else from the key's `toString`. Virtualized rows are listed from data, not the DOM, capped at 100 per node (`moreItems` gives the rest). Past 100 items, `select` takes a label as text instead of an `enum`, so a large table doesn't flood the schema.
- The Electron transport (a main→renderer channel plus an MCP-over-HTTP endpoint in uni-harness, off unless started with `--agent-bridge` and guarded by a bearer token) is recorded in [2026-11-13-electron-reverse-ipc.md](2026-11-13-electron-reverse-ipc.md).
