# `run` and `runOnce` run on the R3 semantics

## Context

Step 3c of `plans/2026-11-21-rx-r3-event-model.md`, first part. After step 3b, `runContinuously`
follows the target model (`spec/lean/UniSpec/RxR3.lean`, `RxR3Ops.lean`): `OnError` passes and
`OnCompletion` ends. `run` and `runOnce` still used a second runner in "default mode", whose
operators treat every error as terminal. The Lean model proves default mode equals the R3 model
with `resumeAsFailure` before the sink for per-event operators, `flatMap`, and `take`, but not for
`recover` over a source error that does not end the source, nor for `recoverWith`.

## Decision

- `run` and `runOnce` use the same runner as `runContinuously`. Their sink ends the run at the
  first `OnError` or `OnCompletion`, delivers an error as `OnCompletion(Result.Failure(e))`, and
  drops later events. The subscription counts as ended for `RxTracker` at that point.
- `GenRxR3Cases.lean` writes every case for both entry points: `continuous` (the model's trace)
  and `run` (the trace with `resumeAsFailure` before the sink), 882 cases replayed by
  `RxR3SpecTest`.
- The old default-mode `recover` cases (`GenRxRecoverCases.lean`, `RxRecoverSpecTest`) are
  removed: they encoded a source `OnError` that ends the source, which the R3 cases replace.
  `RxRecover.lean` stays as the baseline `RxR3.lean` compares against.
- Two operators relied on the old sink accepting events after the end:
  - `throttleLast` now emits the value still waiting for its window before forwarding
    `OnCompletion`, instead of on a timer tick after the end;
  - `onCancel` treats any `OnCompletion` as the end, so `f` does not run after it;
  - the `RxSource` reader (`Rx.queue`, `RxBoundedQueue`) stops at `OnCompletion` in every mode.
    It used to keep reading in continuous mode, and a stopped `RxBoundedQueue` answers every read
    with its end again, so the reader spun forever (it hung the Scala.js suite).
- `run` delivers nothing after its end, even from a live `RxVar` that keeps emitting after a
  throwing `map` or `setException`. Before, default mode kept delivering `OnNext` after
  `OnCompletion(Result.Failure(e))`.

## Consequences

- Breaking: inside `run`, a recovered `OnError` from a source that keeps running (an `Rx.queue`
  given an `OnError`, a throwing `map` over an `RxVar`) lets the stream continue, as R3 says.
  Before, default mode ended the source at the error.
- The `continuous` flag of `RxRunner` is still there: `RxLive.lean` and `RxLiveSpecTest` test
  both modes through runner instances. Removing it (3c, second part) means giving `RxLive.lean`
  one mode.
