# CSV and TSV for Uni (`wvlet.uni.text.csv`)

## Goals

- Read and write CSV and TSV with no extra dependencies, identically on JVM, Scala.js, and Native.
- Decode rows into case classes with Weaver, as `YAML.fromYaml[A]` does, and write case classes back as rows.
- Stream large files row by row, so a multi-GB export never needs to fit in memory.

## Background

- Uni reads and writes JSON, MessagePack, YAML, Markdown, Parquet, and Arrow IPC, but has no CSV codec. `ContentType.TextCsv` already exists.
- Primitive Weavers already accept strings for numbers, booleans, and dates. So a row turned into a `JSONValue` object of strings decodes into a typed case class with `Weaver.fromJSONValue`, with no CSV-specific type logic.
- "TSV" covers two conventions. Some tools write CSV with a tab delimiter, using `"` quoting. Others (PostgreSQL `COPY`, MySQL, "linear TSV") never quote, and escape `\t`, `\n`, `\r`, and `\\` with backslashes. Files from either source are common.
- `FileSystem.readChunks(path)` streams on JVM and Native. On Node it reads the whole file and then splits it into chunks, and in browsers it throws. Object stores and HTTP bodies can also arrive as byte chunks.
- Empty strings don't decode as typed values. `""` fails for `Int` and `Option[Int]` (the Option Weaver only gives `None` for nil), and it silently becomes `false` for `Boolean`. So empty cells must reach Weaver as null.
- The JVM has good CSV libraries already (kantan.csv, scala-csv, fs2-data-csv, Jackson CSV), and they work well in their own stacks. This codec is for code that wants one cross-platform toolkit with Weaver and `IOPath`.

## Design

Lane: Standard — a new public package and API surface.

- **User flow:** a caller has a CSV export (a string, a file path, or a byte stream from S3 or HTTP) and wants rows or case classes. They call `CSV.read[A](text)` or iterate `CSV.readFile[A](path)`, and get a `TextParseException` with line and column when the input is malformed. They write with `CSV.write(rows)` / `CSV.writeTo(path, rows)` and open the result in a spreadsheet or pandas.
- **Entry points** (the same on `TSV`):
  - `parse(text)` returns all rows as `Seq[IndexedSeq[String]]`
  - `read[A](text)` returns `Seq[A]`
  - `reader[A](chunks)` takes an `Iterator[String]` or an `Iterator[Array[Byte]]`
  - `readFile[A](path)` streams a file
  - `write(rows)` and `writeTo(path, rows)` write rows
- **Streaming result:** `reader` and `readFile` return a `CSVReader[A]`, an `Iterator[A]` that is also `AutoCloseable`. It closes its source at the end of input and on a parse error. Callers close it with Uni's `Resource` when they stop early.
- **One package, two entry points:** `CSV` and `TSV` objects share a reader, a writer, and one immutable `CSVFormat` config. `TSV` is a preset, not a separate implementation.
- **Config:** `CSVFormat` with `withDelimiter`, `withQuote`/`noQuote`, `withEscapeStyle` (quoted RFC 4180 vs backslash, the one difference between the TSV presets), `withHeader`/`noHeader`, `withNullString`/`noNullString`, `withRaggedRows` (opt-in padding, because real exports often have short rows), and `withFormulaEscape`. The writer always ends lines with `\n`, as pandas and database tools do. `\r\n` is still read.
- **TSV default:** the backslash-escape style, since that is what database tools emit and it never needs quotes. `TSV.quoted` gives the CSV-with-tabs style for spreadsheets' "save as TSV".
- **Reading CSV:** RFC 4180 rules: quoted fields, embedded delimiters and newlines, `""` escapes. Also LF or CRLF line endings, a leading UTF-8 BOM, and a missing final newline.
- **Rows:** a row is `IndexedSeq[String]`, with exactly the text of each field. For `JSONValue` objects and Weaver decoding, a field equal to the null string becomes `JSONNull`, so `Option` fields get `None` and other fields fall back to their defaults. The null string is an unquoted empty field for CSV, and `\N` for backslash-style TSV. A quoted `""` stays an empty string. Missing columns also fall back to case-class defaults.
- **Headers:** with a header, columns map to fields by name. Duplicate or empty header names are an error. With `noHeader`, `read[A]` maps columns to fields by position. Empty input gives no rows.
- **Errors:** an unclosed quote, a stray quote in an unquoted field, and (by default) a row with a different field count than the header throw `TextParseException` with the line and column. Lenient ragged-row handling is opt-in.
- **Streaming:** the parser is a resumable state machine over char chunks, so a quoted field or a `\r\n` may span chunks. Bytes are decoded with the javalib's incremental `UTF_8.newDecoder`, which carries a split multi-byte character to the next chunk. A test checks it on all three platforms, and if a platform lacks it, a small hand-written UTF-8 carry replaces it. `readFile` streams on JVM and Native. On Node it buffers the whole file (a limit of `readChunks`), and in browsers it is unsupported.
- **Writing:** quote a field only when it contains the delimiter, quote, CR, or LF, or has leading or trailing space. Case classes write with a header from their field names (via Weaver's map form). Nested values (lists, objects) are written as their JSON text.
- **Formula escape:** off by default, because it changes data. When on, a field starting with `=`, `+`, `-`, `@`, tab, or CR gets a leading `'`, the OWASP guidance for files opened in Excel.
- **Docs and skill:** add `docs/text/csv.md`, an entry in `for-ai-agents.md`, and a section in the `uni` skill, with snippets compiled by `docSnippets`.
- **Tests:** RFC 4180 cases, both TSV styles, BOM and CRLF, chunk boundaries inside quoted fields and multi-byte characters, round-trip of write then read, Weaver decoding, and error positions. They run on all three platforms.
- **Out of scope for v1:** lossless round-trip editing, guessing column types, auto-detecting the delimiter, and bridges to Parquet or Arrow.

## Alternatives and Why Not?

- **Build on `ScannerBase` / `LineReader`.** CSV needs a small state machine over chars that resumes across chunks. The existing scanners work on a whole `IArray[Char]` and would block streaming.
- **Separate `wvlet.uni.text.tsv` package.** The two formats share all logic. Two packages would double the API for one config difference.
- **Type inference (numbers, nulls) at parse time.** Weaver already converts strings to the target type. Inference would guess wrong for IDs and zip codes like `007`.
