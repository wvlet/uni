# UiAgent: a typed bridge that lets AI agents read and operate uni-ui

## Goals

- An agent (Claude Code over MCP, or a browser agent over WebMCP) can read a running uni-ui app as structured data and operate it, without screenshots or guessing CSS selectors.
- The app stays in control: it decides what the agent may see and do, can confirm or cancel each agent change, and can tell the agent what the human changed since its last turn.
- Tests drive the UI through the same snapshot/act API that agents use.

## Background

- #898 added `ChangeSource.Agent`, `ChangeSource.withSource`, and `ChangeGate`, so every uni-ui state write already passes an `onChange` hook that can see the source and cancel.
- #898 also added `data-slot` on every part, and #902 added ARIA pattern checks; together they give stable roles and labels to report.
- `MCPServer` (uni) already turns a Scala trait into MCP tools with JSON Schemas built from `Surface`. It serves stdio and HTTP.
- The existing Electron RPC (adr 2026-06-24) only goes renderer → main. UiAgent needs main → renderer, because the MCP server sits in the main process and the UI lives in the renderer.
- WebMCP is experimental in Chrome (flag or origin trial, Chrome 149+). The current API is `document.modelContext.registerTool(tool, { signal })`; the older `navigator.modelContext` / `provideContext()` were removed.
- `DomTestSupport` lives in uni-test, below uni-ui, so it cannot know uni-ui component kinds. Tests use the in-process `UiAgent` API directly; `DomTestSupport` itself does not change.

## Design

Lane: Standard — new public API, and a new tool surface exposed to agents (always-gate).

**Agent flow (Claude Code driving uni-harness)**
- The developer starts uni-harness with the agent bridge on (`--agent-bridge`); the app prints the MCP URL and a token, and the developer adds it to Claude Code.
- The agent calls `ui_snapshot` and gets a compact tree: `ref`, kind, label, value, items, disabled, and the actions available now, each with a JSON Schema.
- The agent calls `ui_act(ref, action, args)`. The change goes through `ChangeGate` with `ChangeSource.Agent`, so the app's `onChange` can cancel it; the result says applied, canceled, or awaiting the human's confirmation.
- Next turn, the agent calls `ui_changes(since)` to see what the human did meanwhile.
- Turning the flag off, or closing the app, removes the endpoint.

**Core API (uni-ui, `wvlet.uni.ui.agent`)**
- `UiAgent` is off until the app installs it: `UiAgent.install(policy)`. It returns a handle with `snapshot`, `act`, `query`, `subscribe`, and `uninstall`.
- Components register themselves on mount and unregister on unmount. First set: Button, TextField, Select, Tabs, Menu, Dialog, Tree, VirtualList/DataTable (selection), CommandPalette. Dock, Panes, and Toast follow later.
- `ref` comes from an explicit `.agentRef("region")` modifier, else from the label, else from kind plus a counter. Refs stay stable while the component is mounted.
- `query` filters the snapshot by kind, label text, or ref prefix, so the agent doesn't load the whole tree.
- `subscribe(change => ...)` delivers every committed `ChangeDetails` with its source. The bridges keep a bounded ring buffer of non-agent changes behind a cursor for `ui_changes(since)`.

**Typed actions**
- Each kind has a fixed action set: `press`, `setText`, `select`, `toggle`, `open`/`close`, `expand`/`collapse`, `sort`. No guessing from method names.
- Argument schemas come from the component's own data. A `Select[Region]` lists its items as a schema `enum` of item refs and labels; the agent picks a listed item, never builds an `A`.
- App-specific commands are an optional trait the app hands to `UiAgent` (`withTools[T](impl)`), with schemas built by the same `Surface`-based `JsonSchema` that `MCPServer` uses.

**Permissions**
- `AgentPolicy` sets what is allowed: `readOnly`, `allowAll`, or `allow(kinds / refs / actions)`. Default when installed: snapshot plus actions on everything not marked otherwise.
- `.agentHidden` removes a component and its subtree from snapshots. `.agentSecret` reports the value as `"<redacted>"`; password fields are redacted automatically.
- `.agentConfirm("Delete project?")` makes an agent's action wait for the human: uni-ui shows a confirm dialog, and the act result reports whether the human approved.
- Every agent change is tagged `ChangeSource.Agent`, so the app's `onChange` handlers can still veto case by case.

**Transports**
- Wire API: a `UiAgentApi` trait plus its case classes in `uni`. The Electron main process and JVM clients can then use it without uni-ui.
- Electron: a reverse channel in `wvlet.uni.electron` (main calls the renderer), built on the same `RPCDispatcher` and envelope as the existing IPC. Preload gets one more handler.
- uni-harness main runs `MCPServer.withTools[UiAgentApi](forwarder)` over HTTP on 127.0.0.1. It runs only when started with `--agent-bridge`, and every request needs a random bearer token generated at startup.
- Browser: when `document.modelContext` exists, `UiAgent.installWebMcp()` registers the same four tools, and unregisters them through an `AbortSignal`. Otherwise it does nothing.
- Tests cover registry and snapshot per component kind, act through `ChangeGate` (cancel and confirm), redaction, the policy, the reverse IPC round-trip, and the MCP tool list in the harness.
- An ADR (`adr/2026-11-13-ui-agent.md`) records the API, the permission model, and the transport choices. The agent docs (`for-ai-agents.md`, the uni skill's `ui.md`) gain a UiAgent section.

## Alternatives and Why Not?

- **Snapshot the DOM/ARIA tree instead of a component registry.** It loses typed values and action schemas, and it is what screenshot and a11y-tree agents already do poorly.
- **Run the MCP server in the renderer.** A sandboxed renderer cannot listen on a port, and it would bypass the main process's control over who connects.
- **Stdio MCP for Electron.** Claude Code would have to launch the GUI app itself; HTTP lets it attach to a session that is already running.
- **Infer actions from method names (`set*`, `open`, `toggle`), as UI SDK does.** Untyped, and it breaks on renames. Uni already knows each component's kind and value type.
- **Ship everything in one PR.** Possible, but large: core, WebMCP, and the ADR are one review, and the Electron reverse channel plus the harness MCP bridge are another. The recommended split is in the approval card.
