# uni-ui: a component kit for uni-dom

## Goals

- Give Uni apps desktop-grade UI components (panes, tabs, menus, dialogs, lists, tables, docks) that
  work the same in the browser and in Electron.
- Stop each app from copying uni-harness's panes, resize handles, tabs, and theme code.

## Background

- [GPUI Kit](https://gpui-kit.com/) (Rust, built on Zed's GPUI) splits unstyled behavior
  (`gpui-base`) from styled components (`gpui-component`), with themes made of semantic tokens.
  uni-ui uses the same split.
- Desktop apps stay on Electron with one Chromium engine, so uni-ui renders to the DOM through
  `uni-dom`, not to a GPU surface. The browser handles accessibility, IME, and text layout.
- `examples/uni-harness` already built and tested `FoldablePane`, `ResizeHandle` (on `PaneResize`),
  `Ui.iconButton`, `Ui.keyCap`, tabs, and light/dark switching. Its styles use Tailwind and its own
  CSS variables.

## Design

Lane: **Standard**, because it adds a new published artifact and new public API (classes, CSS
tokens, and class names).

- **New artifact `uni-ui`**: Scala.js only, package `wvlet.uni.ui`. It depends on `uni.js`, which
  holds the `wvlet.uni.dom.all` DSL and `Storage`, so `uni` itself gains no dependencies.
- **Two layers in one artifact**: `wvlet.uni.ui.base` holds behavior (ARIA, focus, keyboard,
  `data-state`) with no visual classes; `wvlet.uni.ui` holds styled components built on `base`.
- **Styles are a plain CSS file, `uni-ui.css`**, not CSS-in-Scala. Components read semantic
  `--uni-*` variables, themes are variable sets selected by `[data-theme]`, classes are
  `uni-<component>` with `--modifier`s, and every rule sits in `@layer uni` so app CSS wins.
- **CSS distribution in this PR**: the file lives in the jar at `wvlet/uni/ui/uni-ui.css`; in-repo
  apps import it by path. An npm package or an sbt copy task for outside apps comes in a follow-up,
  once the import path is proven.
- **API**: components are `RxElement`s that take the `Rx` values they use, such as
  `Button("Send").primary.onClick(...)`, and `TabList(selected, label)(Tab(...))` with
  `TabPanel(selected)(...)`.
- **Phase 1 (this PR)**:
  - The `uni-ui` project with tests in headless Chromium.
  - The variables, light and dark themes selected by `data-theme`, and a `ColorScheme` helper.
  - `Button`, `IconButton`, `Input`, `Textarea`, `TabList`/`TabPanel`, `FoldablePane`, `Splitter`,
    `StatusBar`, `Kbd`, `Badge`.
  - uni-dom gains `each(items)(key)(render)`, keyed list rendering, so the harness chat thread no
    longer rebuilds (and flickers) on every message.
  - uni-harness moves to the panes, splitter, tabs, and buttons. Its Tailwind layout classes stay.
- **Later phases**, each its own PR:
  - Overlays: Popover, Tooltip, Menu, Dialog, Select, Toast.
  - Collections: VirtualList, Tree, CommandPalette, DataTable.
  - Dock, with a layout that apps can save and restore.
  - Charts, a Markdown view, and maybe a code editor.
- **Tests** cover keyboard and ARIA behavior with `mount`/`fireEvent`. Screenshot goldens wait for a
  later PR, because goldens are per OS and CI runs on Linux.
- **Docs**: a `docs/dom/ui.md` page (setup, components, theming), a `uni-ui` entry in `docs/guide/for-ai-agents.md`
  and the `uni` plugin skill, and `adr/2026-11-05-uni-ui-css-components.md`.

## Alternatives and Why Not?

- CSS-in-Scala: adds runtime work and is harder to override in devtools, and gains little over CSS
  variables.
- Tailwind classes inside the components: every app would have to run Tailwind and scan uni-ui's
  sources.
- Putting it inside `uni.js`: every Scala.js `uni` user would pull in UI code and a CSS file.
- A GPU renderer (Skia on Scala Native): a multi-year project that gives up the browser target.
